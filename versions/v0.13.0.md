# v0.13.0 — 2026-10-23

## Summary
Introduces the Control Plan Evolution engine, migrating Control Plan documents from a flattened line format to a structured, hierarchical V2 architecture with operations, shared equipment resources, process/product characteristics, and granular controls. Adds tenant-level source concurrency fences, lineage and phase binding tracking, content-bound field-level review decisions, validation against customer-neutral quality profiles, landscape multi-page PDFKit export, and an asynchronous approval package pipeline with durable Postgres artifact storage. Retains full backward compatibility with non-destructive lossless upgrade affordances for legacy V1 documents.

## Changes
### Features
- Hierarchical V2 Control Plan Aggregate: Implemented `CpDocumentV2` with operations, equipment resources, characteristics, criteria, and execution rules (`frequency`, `sample_size`, `continuous`, `event_driven`), with bidirectional lossless conversion adapters (`previewV1ToV2Conversion`, `applyV1ToV2Conversion`).
- Operation Lineage & Phase Bindings (`CpLineageService`): Added stable operation identity tracking, process step binding, and typed deep cloning across document revisions and project branches without string-matching guesswork.
- Atomic Source Concurrency Fence (`acquireSourceFence`): Introduced tenant-scoped coarse transaction locking to eliminate synchronization race conditions during concurrent updates.
- Independent Source Adapters & Snapshots (`CpSourceAdapterService`, `CpSourceCaptureService`): Created non-cartesian candidate extraction for PFD, DFMEA, and PFMEA sources with deterministic `sourceSetHash` change detection.
- Content-Bound Review Decisions & Validation Engine (`CpReviewService`): Built review decision tracking with SHA-256 value fingerprints and profile validation runs using customer-neutral baseline `fmeapex-cp-baseline-v1`.
- Multi-Page Landscape PDF Export (`CpPdfService`): Integrated landscape multi-page engineering PDF rendering using `pdfkit`, featuring repeating table headers, page numbers, text wrapping, and approval signature stamps.
- Asynchronous Approval Package Pipeline (`CpApprovalPackageService`): Built CAS lease package worker (`queued` -> `rendering` -> `ready` -> `finalized`), strict creator/approver segregation, and durable database storage for generated artifacts in `CpArtifact`.
- Frontend Operations Workspace & Upgrade UX:
  - Created `ControlPlanV2View.tsx`: Operations sidebar navigator, shared equipment chips, characteristic and control cards, field-level review modal, profile validation findings drawer, and approval intent stepper.
  - Overhauled `ControlPlanWorkspace.tsx`: Dynamic V1/V2 rendering, non-destructive upgrade affordance banner and preview dialog, and unified tabular export projections.

### Fixes
- Injected caller transaction client (`client?: Prisma.TransactionClient`) into `ControlPlanDocumentService.readiness` and `ProjectService.getRevisionReadiness` to prevent escaping active caller transactions.
- Resolved optional control measurement equipment and record references handling in candidate comparisons and exports.

### Refactors
- Added additive Prisma models: `EngineeringSourceFence`, `CpPhaseHead`, `OperationLineage`, `OperationVersionBinding`, `OperationLineageRelation`, `CpRequirementProfileRevision`, `CpSourceCapture`, `CpMutationReceipt`, `CpReviewDecision`, `CpValidationRun`, `CpApprovalPackage`, and `CpArtifact`.
- Added unit and regression test suites: `control-plan-v2.spec.ts`, `cp-lineage.service.spec.ts`, `cp-source-adapter.spec.ts`, `cp-review.service.spec.ts`, `cp-pdf.service.spec.ts`, `cp-approval-package.service.spec.ts`, and frontend `controlPlanV2.test.mjs`.
