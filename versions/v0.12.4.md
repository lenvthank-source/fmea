# v0.12.4 — 2026-10-21

## Summary
Corrected guest account sign-in history tracking, eliminated misleading "Never logged in" admin displays, and updated inactive user archival to evaluate all recorded activity signals. Overhauled project card phase presentation on the dashboard, eliminating the erroneous "PFMEA" phase badge, removing the fixed "24h trial" badge, and applying a subtle yellow whole-card highlight for guest-created projects. Fixed an upstream replication bug that copied document-family selections into project phase metadata.

## Changes
### Features
- Added monotonic session and activity recording helper `backend/src/modules/auth/session-activity.ts` (`recordUserSession`, `recordUserActivity`) to ensure older concurrent requests cannot regress newer timestamps.
- Transactionally initialized `lastLoginAt` and `lastActivityAt` on passwordless guest creation (`createGuestUser`), user signup in both tenant branches (`signup`), and demo try-token creation (`createTryToken`).
- Replaced fire-and-forget password `login` timestamp updates with awaited, tenant/active-scoped monotonic writes with sanitized error logging.
- Exposed `lastActivityAt` additively in `UserService.findAll` selection.
- Overhauled `AdminPanel.tsx` user table: renamed column to "Last Sign-in", replaced misleading "Never logged in" with truthful tiered display ("Sign-in not recorded" with recorded activity timestamp fallback, or "Not recorded" when both null), and clarified archival alert text.
- Introduced pure backend presentation resolver `backend/src/modules/project/project-presentation.ts` (`resolveProjectPresentation`) computing `phase`, `safeLaunch`, `phaseReviewRequired`, and `guestOrigin` without mutating storage.
- Attached `presentation` projection additively to `ProjectService.findAll`.
- Overhauled dashboard grid and list views in `ProjectList.tsx`:
  - Removed erroneous "PFMEA" phase badge; displays recognized base phases (`Prototype`, `Pre-Launch`, `Production`) or `Phase not set` with review guidance.
  - Removed fixed "24h trial" chip completely from project cards and list rows.
  - Applied subtle pale yellow background (`#fffdf0` / `#fff9db` on hover) and border (`#e7d69c` / `#d4bc78` on hover) for guest-created projects, with identical controls and typography.
  - Aligned metric counts and phase filters to use the resolved phase projection.

### Fixes
- Fixed `UserService.checkAndArchiveInactiveUsers`: non-Admin accounts are now only archived when ALL known activity signals (`createdAt`, `lastLoginAt`, and `lastActivityAt`) are strictly older than the 15-day cutoff, preventing active guests with recent recorded activity from being prematurely archived.
- Fixed `ProjectService.replicate`: replaced flawed assignment `documentTypes: dto.includeTypes` with explicit `dto.qualityHeaderOverrides.documentTypes` or source project phase fallback, preventing document-family tokens (`PFMEA`, `PFD`) from poisoning target project phase metadata.
- Updated `ProjectSettings.tsx` phase radio selection to fallback to empty string `''` when unassigned or unrecognized, preventing silent normalization of legacy or review-required phases to `Prototype` upon saving unrelated project metadata.
- Added observable warning logs on token `refresh` and throttled profile `/me` activity update failures instead of swallowing exceptions with empty catches.

### Refactors
- Codified session activity contracts and added 5 new unit tests in `session-activity.spec.ts` and `user.service.spec.ts`.
- Updated `auth-identity.spec.ts` to test guest creation session timestamp initialization and token refresh activity monotonicity.
- Added comprehensive unit test suite in `backend/src/modules/project/project-presentation.spec.ts` (7 tests) verifying order invariance, unrecognized document tokens (like PFMEA), Safe Launch modifier, and reference demo exemptions.

## Schema/Migrations
None (uses existing `lastLoginAt` and `lastActivityAt` DateTime columns on `User` model, and existing `documentTypes` array on `Project` model).

## Breaking / Notes
None. Existing historical accounts with null timestamps are presented truthfully as "Sign-in not recorded" (if activity is known) or "Not recorded", without fabricating dates. Existing project records with legacy or unknown phase tokens display as "Phase not set" with review guidance rather than silently converting to Prototype. Fully backward compatible.
