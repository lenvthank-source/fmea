# v0.2.2 — 2026-08-26
## Summary
Fix `i.filter is not a function` crash caused by paginated `{data,total,page,limit}` vs `[]` contract break, and implement long-term pagination UI across project and FMEA surfaces. Backend now correctly paginates projects (with server-side search), PFMEA rows, and Control Plan rows; frontend unwraps both shapes and renders MUI Pagination/TablePagination.
## Changes
### Fixes
- Fix `TypeError: i.filter is not a function` on `ProjectList` / `PfmeaWorkspace` startup — `project.service.findAll` returned `{data,total}` but frontend expected `[]`; `pfmea-row.service.findAllRows` returned `undefined` (missing `return`).
### Features
- **Pagination UI (long-term):** Projects grid/table: `Pagination` + per-page `Select [9,12,24,48]` (grid uses 9, table 10 default via `DefaultValuePipe(12)`), debounced server search `?search=`, `status` aware, `total` count display. PFMEA / Control Plan / DFMEA tables: `TablePagination` `rowsPerPageOptions [10,25,50]` with `count={total}`. All via `frontend/src/lib/pagination.ts:1` `unwrapPaginated<T>()`.
- **Backend pagination & search:** `project.controller` + `project.service` add `search` param (`partName/orgPartNumber/customer/name contains` insensitive) + `ParseIntPipe` + `DefaultValuePipe(1/12)`. `pfmea-row.controller/service` add `ParseIntPipe(1/25)` and fix missing return. `control-plan-row.controller/service` add full pagination `?page&limit` with `count`.
