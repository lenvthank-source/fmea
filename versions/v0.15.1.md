# v0.15.1 — 2026-10-23

## Summary
Fixes PostgreSQL UUID column data crash (`PrismaClientKnownRequestError`) in `CpReviewService.runValidation` caused by passing non-UUID profile keys into `cp_validation_run.profile_revision_id`. Additionally enables explicit persistence for unpersisted initial Control Plans (`version === 0`) via "Save initial plan" in `ControlPlanToolbar`, unblocking revision submission readiness.

## Changes
### Fixes
- Fixed UUID Column Crash in Validation: Added `toUuidOrNull` validator to `CpReviewService` and `CpApprovalPackageService`. Baseline requirement profile validation now records `null` for `profile_revision_id` in PostgreSQL while returning `'fmeapex-cp-baseline-v1'` to the frontend/API, preventing database type errors.
- Actor ID Sanitization: Sanitized `actorId` in `CpValidationRun` creation using `toUuidOrNull` to guard against non-UUID actor identifiers.
- Enabled Initial Plan Saving: Updated Save button disabled predicate in `ControlPlanToolbar.tsx` to remain active when `props.version === 0`, displaying "Save initial plan" and allowing users to explicitly save newly initialized plans before editing.

### Refactors
- Reusable UUID Validation: Exported `toUuidOrNull` helper from `cp-review.service.ts` for safe boundary conversions across Control Plan services.
- Test Mock Alignment: Updated `cp-approval-package.service.spec.ts` test fixture to use `null` for baseline validation run `profileRevisionId`.
