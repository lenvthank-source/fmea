# v0.8.1 — 2026-10-18

## Summary
Remediates authentication flow and client-side security according to the CIA Triad (Confidentiality, Integrity, Availability). Completely removes client-side credential exposure and "Fill Admin Credentials" actions from Login. Eliminates the intermediate login screen so that visitors clicking "Launch Sandbox" or navigating to the workspace directly auto-initialize the guest session and enter the dashboard immediately. Enforces that the Administrator Sign In window appears strictly after explicit sign out from the app dashboard, with empty credential fields and a zero-friction fallback to the guest sandbox.

## Changes
### Security & Fixes
- **Confidentiality (Zero Credential Exposure)**:
  - Purged the "Fill Admin Credentials" button, exposed corporate email (`lenvthank@gmail.com`), and hardcoded password strings from `Login.tsx`.
  - Configured email and password input fields to start strictly empty (`""`), requiring legitimate manual authentication.
- **Availability (Direct Entry Without Intermediate Window)**:
  - When opening the application or clicking "Launch Sandbox" from the landing page, navigation header, or marketing widgets, the app directly initializes the guest session and opens the dashboard (`/app/projects`) immediately with zero intermediate prompts.
  - Enhanced `ProtectedRoute` in `router.tsx` to automatically initialize the guest session on direct entry if unauthenticated, unless the user has explicitly signed out.
- **Integrity & Access Control (Admin Window Post-Logout Only)**:
  - Configured `AppShell.tsx` "Sign Out / Switch to Admin" action to mark `logged_out: true` in `sessionStorage` and route to `/login`.
  - When `logged_out` is set, `/login` renders the dedicated **Corporate & Administrator Sign In** window with standard security controls, tenant-isolated authentication, and a clear button to return to the guest sandbox.
